# 02 · 数据处理

> 从"通过筛选的视频"到"可训练样本"。核心链路四步：**变步长采样 → 视觉塔抽特征 → 时间戳保真 → 占位符/标签构建**。其中①③是 CST-SSM 的命门，本篇重点讲清楚。

---

## 1. 内容自适应变步长采样（`adaptive_sampler.py`）——命门①

### 1.1 为什么不能等间隔

朴素做法 `ts = arange(T) * (1/fps)` 得到**恒定 Δt**。后果：
- EACS 的连续变步长扫描 `Ā=exp(λ·Δt)` 退化为固定步长 → 与原生 Mamba 无差别；
- Theorem 1 的"更新数 ∝ 事件密度 V_T / 与时长无关"**无法演示**；
- 组 5 消融的 Pareto 曲线画不出斜率，C2 主张塌掉。

> 旧 stand-in（`qwen3_vl.py` 里 `ts = np.arange(T)*tp/fps`）是等间隔，**已被 `encode_video_at` 取代**：按采样器给的 `frame_idx` 精确解码那几帧、每帧独立成一个真实时间戳（见 §2）。

### 1.2 采样策略（三选一 + 组合）

| 策略 | 原理 | 产出 Δt | 适用 |
|---|---|---|---|
| `uniform` | 固定 fps | 恒定 | 仅基线对照 / VFR 的"均匀对照臂" |
| `adaptive`（推荐） | 帧间差分/光流幅度累积到阈值就采一帧 | **真可变**：动则密、静则疏 | 主训练 & 效率实验 |
| `scene` | 场景切换检测（直方图突变）为硬采样点 + 段内自适应 | 可变 + 语义边界对齐 | 定位增强 / CSG |

**adaptive 核心算法**（累积显著性触发）：
```
acc = 0；上一采样帧 = 帧0（必采）
for 每个候选帧 k（以高 fps 粗扫）:
    acc += 显著性(帧k, 上一采样帧)      # 归一化帧差 or 光流幅度均值
    if acc ≥ θ 或 (t_k - t_last) ≥ Δt_max:   # 够变了，或到最大间隔强制采
        采样帧 k；记录真实时间戳 t_k；acc=0；上一采样帧=k
    # 静止段落 acc 长期不涨 → Δt 自然拉大 → 稀疏
```
- `Δt_max` 兜底：即使全静止也周期性采样（配 `θ`、`Δt_max`、`Δt_min` 于 `pipeline.yaml`）。
- `Δt_min` 上限帧率：防止高动态段过采爆帧数。
- **同时输出 `event_density`**：`采样帧数 / 时长`，回填 `filtered.jsonl` 供分层（见 01 文档§4.2）。

### 1.3 时间戳真实性契约

采样器输出的 `timestamps[L]` 必须是**每帧在原视频中的真实秒级时刻**（严格单调递增），不是索引×步长。下游 `collate_fn` 依赖单调性做 `searchsorted` 连续查询，`validate_dataset.py` 强校验单调。

## 2. 视觉塔离线抽特征（`extract_features.py`）——一次加工地基

### 2.1 流程

```
视频 → adaptive_sampler 选帧(真Δt) → Qwen3-VL 视觉塔 → 帧级 patch 特征[L,P,d]
     → 空间池化到目标 P → float16 → {vid}.npz(features, timestamps)
```

- **模型**：`Qwen3-VL-4B/8B` 视觉塔（`out_hidden=3584`）；由 `Qwen3VLVisionFeatureExtractor.encode_video_at(video, frame_idx, ts, target_patches)` **按采样器帧索引精确取帧**（decord 随机访问），非 processor 默认均匀 fps。
- **每帧独立成时间戳**：把每采样帧当作独立"图像"预处理，使视觉塔的 `temporal_patch_size=2` **不会把两个非均匀采样帧合并**成一个时间栅格——这是真实可变 Δt 保真的落地点。
- **空间维 P 的选择**（直接决定存储，见 03/04 文档）：
  - `P=1`：全局池化（CLS 或均值），最省，适合纯时序任务；
  - `P=9`（3×3）**推荐**：保留粗空间结构，兼顾定位；
  - `P=64+`：细粒度，存储爆炸，仅小规模消融用。
  - 逐帧 token 按 `image_grid_thw` 分段、各自池化到 P（兼容 Qwen 动态分辨率，逐帧 Hp/Wp 可不同）。
- **dtype**：存 `float16`（`dataset.py` 索引后转 float32），省一半盘。

### 2.2 关键实现要点

- **批处理与显存**：视觉塔逐视频前向，帧数多时分块（chunk）过塔再拼接，避免 OOM。
- **幂等/断点续跑**：已存在且校验通过的 `{vid}.npz` 跳过（`--skip-existing`），大规模抽取必备。
- **确定性**：采样与池化不引入随机；同一视频重复抽取结果一致（便于复现）。
- **失败隔离**：单视频异常写入 `extract_failed.jsonl` 并继续，不中断整批。
- **dry-run**：无 GPU/transformers/decord 时用合成变步长特征跑通链路（自测）。
- **可验证性**：真实抽取的"取帧→预处理→视觉塔→分段池化→时间戳对齐"逻辑由 `tests/regression_qwen_extract.py` 用 torch stub 在 CPU 全覆盖（无需 GPU）。

### 2.3 feat_dim 契约

抽取器的 `out_hidden` 必须等于 `CSTSSMConfig.feat_dim`。换视觉塔（如换 8B）→ 同步改配置，否则 `FeatureAdapter` 维度不匹配。

## 3. 文本 / 标签构建（`build_manifest.py`）——命门②占位符对齐

### 3.1 占位符数量必须 == subsample 后有效帧数

- `Qwen3VLLanguageModel._scatter_visual`（`qwen3_vl.py:70`）把视觉状态写入 prompt 中 `<video>`(id=151656) 位置，**约定二者数量相等**。
- 但 `VideoTemporalDataset._subsample`（`dataset.py:61`）在 `L > max_frames(512)` 时会**把帧数砍到 512**。
- 若 manifest 里按原始 L 写占位符 → 错位；代码有补零兜底但是**静默降质**。

**两种对齐方案**（`build_manifest.py --placeholder-mode`）：

| 模式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| `expand`（严格） | manifest 写死 `min(L, max_frames)` 个 `<video>` | 与 stand-in 完全一致 | 与 max_frames 耦合，改配置要重建 |
| `single`（推荐） | prompt 只放 **1 个** `<video>`，**运行时按有效帧数展开** | 解耦、manifest 干净 | 需在 dataset/injection 侧支持展开（见下） |

> 推荐 `single`：`build_manifest.py` 写单占位符，同时在 README 契约里要求注入侧"1 个占位符 → 展开为 L 个 soft-token"。这样 max_frames 变化不必重建 manifest。当前 stand-in 是"逐占位符对齐"，落地 Qwen3-VL 时按 `single` 语义在注入处展开即可。

### 3.2 标签构建（按任务类型）

| task_type | prompt | answer / 标签 |
|---|---|---|
| `qa` | `<video> {question}` | 答案文本；labels 对 prompt 段打 -100（只学答案） |
| `caption` | `<video> Describe...` | 字幕文本 |
| `grounding` | `<video> When does X happen?` | `from {s}s to {e}s` + 结构化 `gt_start/gt_end`（毫秒级，供 CSG 评测） |
| `causal` | `<video> Why...` | 因果解释文本 |

- 复用 `ByteTokenizer.build_lm_example`（stand-in）或 Qwen tokenizer（生产）。
- **grounding 的 `gt_start/gt_end` 必须毫秒精度**：CSG 亚帧定位判据 `MAE/floor` 依赖标注精度；标注比 δ/4 还粗会污染 GATE-6。

## 4. 处理阶段的产物与校验

- 产物：`features/{vid}.npz`（或转 `.npy+.ts.npy`）+ `manifests/{split}.jsonl`。
- 立即过 `validate_dataset.py`：占位符数、时间戳单调、维度一致、引用可达四项（见 03 文档§4）。
- 采样可视化（可选）：`stats.py --plot-dt` 画某视频的 Δt 序列，肉眼确认"动密静疏"，防止采样器退化成均匀。
