# 04 · 训练本算法需要多少数据、多少显卡

> 本篇给出**可执行的数据量与算力预算**，与《实验执行清单》的 GPU·h 汇总对齐，并补上清单遗漏的两块：**数据处理（特征抽取）算力**与**特征缓存存储**。所有数字给"推荐档"和"最小可投档"两栏，按你集群规模线性缩放。

---

## 1. 需要多少数据

### 1.1 分阶段数据量

| 阶段 | 用途 | 数据来源（示例） | 推荐档 | 最小可投档 | 依据 |
|---|---|---|---|---|---|
| **Stage-1 自监督预训练** | 学连续时序动力学（否则门控无判据） | InternVid / HowTo100M 子集 + Ego4D + 自有长视频 | **30–50 万**长视频，均 3–10 min（≈ 2–5 万小时、~2–4 亿帧@自适应采样） | **8–10 万**视频；或**直接热启底座权重、砍此阶段** | 时序自监督需覆盖秒级→分钟级动力学，量级参考 InternVid/VideoMamba 预训练 |
| **Stage-2 端到端微调** | 适配下游 + 指令跟随 | LLaVA-Video-178K / VideoChat2-IT / VideoInstruct-100K | **40–80 万** QA 对（10–20 万视频） | **15–20 万** QA | 对齐 Vamba/Video-LLaVA 指令微调规模 |
| **定位增强**（Stage-2 内混入） | 亚帧定位能力（喂 CSG/VFR） | Charades-STA / ActivityNet-Captions / QVHighlights / DiDeMo | **3–5 万**带毫秒段标注 | **1 万** | 无定位数据则 GATE-6 穿透 δ/4 学不动；建议占 Stage-2 ≥15% |
| **四基准评测**（仅推理，不训练） | 填 SOTA 表 | MLVU / LVBench / VideoMME / EgoSchema | 官方集，合计 **~1.2 万** QA | 同左 | GATE-4 硬门槛 |
| **CSG / VFR 杀手锏**（合成） | novelty 防线 | 由带精标注视频**重采样合成** | **0.5–2 万**条 | 0.5 万 | GATE-6；`benchmarks/*_build.py` 生成 |

### 1.2 为什么是这个量级（关键取舍）

- **Stage-1 是算力/数据大头，但可砍**：若底座（Vamba/Video-LLaVA）已在大规模视频上预训练，可**热启其权重、跳过 Stage-1**，用 Stage-2 直接微调 EACS。最小可投档正是走这条路，省下 2,000–4,000 GPU·h。
- **不能砍的是"分层覆盖"而非"绝对量"**：即便数据少，也**必须覆盖低/中/高事件密度三档 + 长时长桶**（见 01 文档§4）。否则 Theorem 1 的"更新数 ∝ V_T"斜率、显存-时长解耦曲线画不出来——这比总量更致命。
- **定位数据是隐形刚需**：常规 video-QA 里几乎没有毫秒级时间段标注，必须专门引入 Charades-STA 一类，否则杀手锏实验（占全篇 novelty 防线）无从训练。

### 1.3 帧数换算（决定存储与抽取算力）

自适应采样后**有效帧数**远少于按高 fps 全抽：
- 均匀 2 fps、10 min → 1200 帧；
- 自适应（动密静疏，均值 ~1 fps 等效）→ **~600 帧/10min**，`max_frames=512` 再截断。
- 全库有效帧数 ≈ Σ(时长 × 等效采样率)。推荐档 Stage-1 ≈ **2–4 亿帧**（用于下面存储估算）。

## 2. 需要多少显卡

单位基准：**8×A100-80G 或 8×H100-80G 单节点**。显存靠 **LoRA（可训 ~7.5%）+ EACS 分块梯度检查点 + bf16 + 梯度累积 + 8bit AdamW（可选）** 压住，8×80G 足以全流程跑通。

### 2.1 训练算力（对齐实验清单汇总表）

| 阶段 | 内容 | GPU·h（A100/H100-80G） |
|---|---|---|
| 0 | 基线复现 | 200–400 |
| 1 | EACS 算子实现调试 | 150 |
| 2 | Stage-1 自监督预训练 | 2,000–4,000 |
| 3 | Stage-2 端到端微调 | 800–1,500 |
| 4 | 四基准评测（推理） | 300 |
| 5 | 效率曲线 | 150 |
| 6 | CSG/VFR 杀手锏 | 250 |
| 7 | 五组消融 | 400 |
| **合计** | | **≈ 4,250–7,150 GPU·h** |

- 8×80G 满负荷：约 **22–37 天**（建议排 6–8 周含调试余量）。
- **最小可投档**（砍 Stage-2 的 Stage-1、单底座、热启权重）：**≈ 2,000–2,800 GPU·h**，8 卡约 **10–15 天**。

### 2.2 ⚠️ 数据处理算力（清单遗漏，需单列）

**特征抽取本身是一个不小的离线 GPU 作业**，不含在上面的训练预算里：

- 视觉塔（Qwen3-VL-4B 塔）抽帧吞吐 ≈ **50–100 帧/s/卡**（A100，bf16，含解码）。
- 推荐档 Stage-1 ~2–4 亿帧 → `2e8 / (75 帧/s) / 3600 ≈ 740` GPU·h（取中值）。
- 加 Stage-2 视频 ≈ 合计 **600–1,200 GPU·h**。
- **完全可并行**（`extract_features.py --shard i/N`），8 卡 ≈ **3–6 天**；多机线性缩短。

> 结论：把这块算进去，**端到端总预算 ≈ 5,000–8,400 GPU·h（推荐档）**。最小可投档因数据少 + 砍 Stage-1，抽取降到 ~150–300 GPU·h。

### 2.3 硬件配置建议

| 档位 | 配置 | 周期 | 适用 |
|---|---|---|---|
| **最低门槛** | 1×(8×A100-80G) 节点 | ~2–5 周 | 能全流程跑通，最小可投档 |
| **推荐** | 2×(8×A100/H100-80G) = 16 卡 | ~2 周 | 推荐档，周期压到两周 |
| **舒适** | 4 节点 32 卡 | ~1 周 | 多消融并行、快速迭代 |

- 单卡显存下限：**80G**。40G 卡需进一步降 batch / 升梯度累积 / 缩 max_frames，可行但慢。
- 互联：Stage-1/2 用 ZeRO-2（清单指定），多机需 InfiniBand/NVLink 保证 all-reduce 不成瓶颈。
- 抽取阶段对互联不敏感（各卡独立），可用低配/抢占式实例省钱。

## 3. 需要多少存储（清单遗漏，特征缓存是大头）

`bytes ≈ 有效帧数 × P × d × 2`（float16），d=3584。

| 场景 | 有效帧数 | P | 每帧 | 总量 |
|---|---|---|---|---|
| Stage-1 推荐档 | ~3 亿 | 1 | 7 KB | **~2 TB** |
| Stage-1 推荐档 | ~3 亿 | 9（推荐） | 63 KB | **~18 TB** |
| Stage-2 推荐档 | ~5 千万 | 9 | 63 KB | ~3 TB |
| 最小可投档 | ~5 千万 | 9 | 63 KB | ~3 TB |

- **推荐档合计 ≈ 8–20 TB**（主要由 P 决定）。若存储紧张，**P=1 全局池化**可压到 ~2–3 TB，代价是牺牲部分空间定位能力（对纯时序任务影响小）。
- 原始视频抽完特征即可归档/删除，不占训练热存储。
- `.npy+.ts.npy` 分离格式（见 03 文档）不额外增大存储，但换来真 mmap，训练 IO 友好。

## 4. 一页速查

```
推荐档（走全流程）
  数据：Stage-1 30–50万长视频 + Stage-2 40–80万QA + 定位3–5万 + 评测1.2万
  显卡：训练 4,250–7,150 GPU·h + 抽取 600–1,200 GPU·h ≈ 5k–8.4k GPU·h
        → 16×80G 约 2 周
  存储：8–20 TB 特征缓存（P=9）

最小可投档（热启底座、砍 Stage-1、单底座）
  数据：Stage-2 15–20万QA + 定位1万 + 评测1.2万 + CSG/VFR 0.5万
  显卡：训练 2,000–2,800 GPU·h + 抽取 150–300 GPU·h
        → 8×80G 约 10–15 天
  存储：~3 TB（P=9）或 ~1 TB（P=1）

不可妥协项（无论哪档）：
  ① 真实可变 Δt（adaptive 采样）  ② 事件密度三档覆盖  ③ 毫秒级定位标注  ④ 评测泄漏检查
```
