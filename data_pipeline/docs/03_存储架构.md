# 03 · 存储架构

> 数据落盘方式直接决定训练时的 IO、内存与可扩展性。本篇给出目录规范、manifest schema、特征存储格式选型（mmap）、分片策略与放行校验。

---

## 1. 目录规范

```
data/                              # data_root（传给 VideoTemporalDataset）
├── raw_videos/                    # 原始视频（处理后可归档/删除）
├── filtered.jsonl                 # 筛选通过清单（含时长桶/事件密度/pHash）
├── rejected.jsonl                 # 剔除清单 + 原因（可审计）
├── features/                      # 小规模：.npz（features+timestamps 同档）
│   └── {vid}.npz
├── features_npy/                  # 规模化：分离 .npy（真 mmap，推荐）
│   ├── {vid}.npy                  #   features [L,P,d] float16
│   └── {vid}.ts.npy               #   timestamps [L] float32
├── manifests/
│   ├── train.jsonl                # 每行一个 VideoSample
│   ├── val.jsonl
│   ├── videomme.jsonl             # 评测集（convert_benchmarks 产出）
│   └── csg.jsonl / vfr.jsonl      # 杀手锏基准
└── stats/                         # 分布直方图、Δt 可视化（附录素材）
```

`feature_ref` 在 manifest 里写**相对 data_root 的路径**（如 `features_npy/vid0001.npy`），`data_root` 训练时传入，便于整目录迁移。

---

## 2. manifest schema（对齐 `cst_ssm/data/schema.py::VideoSample`）

每行一个 JSON 对象：

```json
{
  "video_id": "vid0001",
  "feature_ref": "features_npy/vid0001.npy",
  "prompt": "<video> When does the person open the fridge?",
  "answer": "from 12.30s to 15.80s",
  "task_type": "grounding",
  "timestamps": null,                 // 特征模式下由 .ts.npy 提供，可省
  "duration": 63.24,
  "gt_start": 12.300,                 // 毫秒级；grounding/CSG 必填
  "gt_end": 15.800,
  "split": "train"
}
```

- 字段以 `VideoSample` 为准，多余字段忽略、缺省字段用 dataclass 默认。
- `feature_ref` 指向 `.npy` 走真 mmap；指向 `.npz` 会整载（见§3）。
- 写入用 `ensure_ascii=False`，保留中文可读。

---

## 3. 特征存储格式选型：`.npz` vs `.npy`（规模化必读）

`cst_ssm/data/dataset.py::_load_feature` 的注释已点破关键差异：

| 格式 | 读取方式 | 内存 | 适用规模 | 命令 |
|---|---|---|---|---|
| `.npz`（features+timestamps 同档） | **`np.load` 整档解压**（mmap 对 zip 无效） | 每次读整个视频特征进内存 | ≤ 数千视频 / 帧数小 | `prepare_features.py` 默认 |
| `.npy` + `.ts.npy`（分离） | **`mmap_mode='r'` 真惰性**，按 subsample 索引只读需要的帧 | 只驻留被索引帧 | 十万级 / 长视频 | `npz_to_npy.py` 转换 |

**结论**：小规模自测用 `.npz` 方便；**正式训练前务必 `npz_to_npy.py` 批量转 `.npy+.ts.npy`**，否则长视频（数千帧×P×3584）整载会拖垮 dataloader 内存与吞吐。

存储量级（float16）：`bytes ≈ L × P × d × 2`。单帧 d=3584：
- P=1 → 7 KB/帧；P=9 → 63 KB/帧；P=64 → 448 KB/帧。
- 详细全库估算见 `04_数据量与算力.md §3`。

## 4. 放行校验（`validate_dataset.py`）——四项硬约束

进训练前**必须**全过，`--strict` 下任一失败即非零退出、拒绝放行：

| # | 校验 | 判据 | 违反后果 |
|---|---|---|---|
| ① | **时间戳单调** | `all(ts[1:] > ts[:-1])`（严格递增，秒） | 连续查询 `searchsorted` 错、Δt 出负 → 扫描 NaN |
| ② | **占位符对齐** | prompt 中 `<video>` 数 == `min(L, max_frames)`（`expand`）或 ==1（`single`） | 视觉状态错位注入 → 语义乱、定位错 |
| ③ | **维度一致** | 所有特征 `d == feat_dim`；`P` 一致 | FeatureAdapter 维度崩 |
| ④ | **引用可达** | `feature_ref` 文件存在、可加载、`.npy` 有配套 `.ts.npy` | 训练中途 IO 报错 |

附加软检查（warning）：Δt 分布是否退化为常数（提示采样器可能没生效）、grounding 标注是否落在 `[0, duration]` 内、事件密度分层是否覆盖三档。

---

## 5. 分片与并行（大规模）

- **manifest 分片**：`train.jsonl` 过大时切成 `train.part-{000..N}.jsonl`，训练侧用 `ConcatDataset` 或按 rank 分配，利于分布式各 worker 只读自己分片。
- **特征分桶目录**：`features_npy/{vid[:2]}/{vid}.npy` 两级散列，避免单目录几十万文件拖垮 inode/ls。
- **抽取并行**：`extract_features.py` 天然可 embarrassingly parallel，按 `--shard i/N` 切分视频清单多机/多卡并跑（见 04 文档算力）。
- **冷热分离**：`raw_videos/` 抽完特征即可归档到冷存储；训练只依赖 `features_npy/` + `manifests/`。

## 6. 可复现与审计

- 每次流水线运行记录 `configs/pipeline.yaml` 快照 + git commit + 处理计数到 `stats/run_manifest.json`。
- `rejected.jsonl` 保留每条剔除原因，评审质疑数据时可回溯。
- 评测泄漏：训练集 pHash 与四基准/CSG 源比对结果落盘（`stats/leakage_check.json`），投稿附材料。
